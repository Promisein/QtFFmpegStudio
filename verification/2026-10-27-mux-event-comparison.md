# Mux 事件驱动对照（2026-10-27）

## 方法

同一台 Windows 11 机器、同一个 1080×1728、30 fps、4 秒的合成 MPEG-4/AAC 输入；H.264/AAC 输出、正常速度，不旋转。使用同一个输入文件、同一编码设置及交替顺序，CPU 软件和 NVENC 分别预热一次、测量三次。CPU 使用 CRF 23，NVENC 使用 VBR CQ 23，两者画质未校准；数值只能比较同一编码后端前后变化。基线为提交 6885f7d 的程序；事件阶段仅修改等待与交错顺序，仍保留原音频时间戳重建；最终阶段保留 AAC 编码器时间戳。

各次进程与 mux 计时见 [原始数据](2026-10-27-mux-event-runs.csv)。单独运行三次采样每个后端进程的 Windows GetProcessTimes（用户态与内核态之和）和 GetProcessMemoryInfo（PeakWorkingSetSize）；结果见 [资源记录](2026-10-27-mux-resource-runs.csv)。工作集包含编码器和 DLL 等整个进程，不能归因于 mux；CPU 时间为线程累计值，可以大于墙钟时间。所有性能数值受机器负载影响。

最终 sleep_ms 为 0；wait_ms 是实际进入条件变量等待的调用累计时间（包括唤醒调度和取包），并非 CPU 忙等。最终 CPU / NVENC 的进程墙钟中位数分别较本次基线下降约 83% / 86%。实际收益因素材、机器和负载而异。

资源单独采样中位数：CPU 软件编码基线 / 最终 CPU 时间约 5891 / 5484 ms，工作集峰值约 1208 / 1203 MiB；NVENC 基线 / 最终 CPU 时间约 547 / 594 ms，工作集峰值约 280 / 281 MiB。CPU 线程累计时间并未按墙钟同比减少；不能将其解释为 CPU 忙等比例。队列为无界 FIFO，峰值 190 包仅是本样本的观察值，长视频或两路速度差异较大时可能增长。

## 正确性及边界

最终六个测量输出均通过 FFmpeg 完整解码，含 120 个视频包和 189 个音频包；逐包 ffprobe 检查每条流的 DTS 严格递增。AAC 首包保留负时间戳及跳过采样信息；自动测试覆盖编码延迟、CPU/NVENC、旋转、倍速、帧率调整、批量及取消。队列单测覆盖两路先后到达、EOF、停止和错误唤醒。

特殊素材仍有既有时间线限制：带约 0.476 秒输入音频起始偏移的样本，输出音频从 0 秒开始；不规则 VFR 样本输入视频 4 秒 / 47 帧，输出视频约 1.84 秒 / 47 帧，音频约 4.02 秒。这是上游按帧序和采样数重新生成时间线所致；本次没有实现保留源起始偏移或 VFR 时间戳，不能声称这些素材音画同步正确。
