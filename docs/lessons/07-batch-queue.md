# 第七课：用表格管理批量转码队列

这一课把第五课的单文件后端扩展到多个任务，但同一时刻只运行一个转码进程。界面增加“批量队列”页签：可一次添加多个 MP4，自动生成不同的输出文件名，并看到每个文件的等待、运行、成功、失败或取消状态。

## 一、在 CLion 中操作

1. 关闭正在运行的 QtFFmpegStudio，重新加载 CMake 并构建 `QtFFmpegStudio`。根目录的 `main.cpp` 仍是唯一应用入口。
2. 打开“批量队列”页签。可以先选批量输出目录；不选时，默认使用第一项输入文件的目录。
3. 在主窗口设置旋转、倍速和编码器，然后点击“添加 MP4 文件…”，一次选两个或更多**有视频和音轨**的 MP4。参数会在添加时复制进每个任务；之后改动上方控件不会改变已排队任务。
4. 查看表格的输入和自动生成的输出路径。点击“开始队列”，观察状态由“等待”到“运行中”，最终分别变为“成功”或“失败”。输出名默认是 `原文件名_batch.mp4`；若已存在，使用 `_batch_2.mp4` 等名称。
5. 试一次“停止队列”：当前任务被请求取消，尚未开始的任务标为“已取消”。处理结束后可以点击“清空任务”再试。

单文件页、模拟页与批量队列互斥。批量运行时，上方文件选择和参数控件不可修改。关闭窗口会先询问，确认后停止队列并等待子进程退出。

## 二、读模型：一行就是一个任务

[batchtaskmodel.h](../../src/batchtaskmodel.h) 中的 `BatchTask` 保存一份 `TranscodeOptions`、状态和结果说明。[batchtaskmodel.cpp](../../src/batchtaskmodel.cpp) 继承 `QAbstractTableModel`：`rowCount()` 返回任务数，`columnCount()` 当前返回五列（第八课增加了解封装列），`data()` 把任务转换成表格文字。新增行前后调用 `beginInsertRows()` 和 `endInsertRows()`；改变状态后发出 `dataChanged()`，表格因此刷新。[Qt QAbstractTableModel 文档](https://doc.qt.io/qt-6.8/qabstracttablemodel.html)说明了这些接口和模型与视图的关系。

试着在 `addFiles()` 中寻找输出名称的生成循环：它同时检查磁盘上已有的文件和本次队列已经预留的路径。重复输入、非 MP4、失效文件会被跳过。任务添加后，输入、输出和参数都固定为当时的快照。

## 三、读调度：一个进程接一个进程

[batchwidget.cpp](../../src/batchwidget.cpp) 使用一个 `BackendProcess`。`startQueue()` 将队列标为运行，`startNext()` 找到下一项“等待”任务，再调用后端。后端发出 `finished` 信号后，模型记录结果，并通过事件循环安排下一项。因此前一项失败也不会阻止后续项运行。[Qt QProcess 文档](https://doc.qt.io/qt-6.8/qprocess.html)说明了异步进程退出信号。

启动每一项前会再次检查输入和输出：如果输出文件在排队后被其他程序创建，该项会标为失败。即使文件在这次检查之后才出现，后端最后发布文件时也会拒绝替换它；本课用[安全发布测试](../../tests/test_safe_output.cpp)固定了这个行为。批量模式从不传 `--overwrite`。单文件模式仍保留自己的覆盖确认。

“停止队列”先把尚未运行的项标为“已取消”，再请求当前后端退出。后端先写输出目录中的 `QFS*.tmp` 临时文件，成功后才发布最终 MP4；强制停止时可能留下这个临时文件，但不会把它标为成功。日志框显示当前各项的后端日志；表格“结果”列保留每项最终说明。

## 四、与主窗口怎样互斥

[mainwindow.cpp](../../src/mainwindow.cpp) 将 `BatchWidget` 加入第三个页签，并接收 `activeChanged` 信号。批量开始后，主窗口禁用单文件转码、模拟启动和参数编辑；批量结束后恢复。关闭确认期间，即使短任务已经结束，窗口也会重新检查状态后处理关闭请求。

## 五、验证与练习

本机自动测试包含：输出名冲突、重复文件跳过、参数快照、三个任务顺序执行且中间失败后继续、排队后输出被占用、停止当前和剩余任务、与主窗口其他任务互斥、关闭确认期间任务结束。构建后可运行：

```powershell
$env:PATH = 'D:\QT\Tools\mingw1310_64\bin;D:\QT\6.8.3\mingw_64\bin;' + $env:PATH
cmake --build .\cmake-build-debug-mingw_qt_683
ctest --test-dir .\cmake-build-debug-mingw_qt_683 --output-on-failure
```

请自己完成两项练习：

1. 添加任务后再把倍速从 1.0x 改成 2.0x。阅读 `BatchTaskModel::addFiles()`，解释已排队任务为什么仍用 1.0x。
2. 先排队，再手工创建其中一项的输出文件。启动队列，确认该项显示失败、已有文件未被覆盖，而下一项仍能执行。

第七课当时表格只有任务状态。第八课已增加解封装百分比；它仍不是可靠的全流程百分比。后续如要显示全流程进度，需要后端定义结构化进度消息并处理各阶段的进度语义。
