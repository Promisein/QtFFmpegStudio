# 学习路线：从 QtHelloWorld 到桌面转码工具

制定日期：2026-10-24。以下是计划，不是功能完成清单。

## 推进顺序

| 阶段 | Qt 知识 | 做出的功能 | 完成标准 |
| --- | --- | --- | --- |
| 0：准备 | Qt 模块、工具链、CMake | 明确环境和目录 | 能找到正确的 Qt 与编译器路径 |
| 1：主窗口 | QApplication、QMainWindow、布局、connect | 窗口、按钮、状态文字 | 点击后文字变化；调整窗口大小时布局正常 |
| 2：文件选择 | QFileDialog、QLineEdit、QString、父子对象 | 选择输入 MP4 和输出文件 | 取消选择不清空旧值；空路径、相同输入输出不能启动 |
| 3：参数设置 | QComboBox、QDoubleSpinBox、QFormLayout | 旋转、倍速、编码器 | 读取控件后形成独立配置，日志中显示准确值 |
| 4：模拟任务 | QTimer、事件循环、控件状态 | 明确标注的模拟进度 | 窗口持续响应；重复启动被阻止；能结束与重试 |
| 5：真实转码 | QProcess、异步信号、日志解码 | 调用自己的 FFmpegProject 后端 | 成功与失败都可见；路径含空格可处理；输出可播放 |
| 6：工程完善 | 状态机、QSettings、部署工具 | 保存配置、打开输出目录、部署 | 重启保留有效设置；退出运行中任务有明确行为 |
| 7：批量与进度 | 表格与模型、任务调度、结构化消息 | 多文件、任务状态、真实进度 | 每个任务独立输出；失败不冒充成功；并发数可控 |
| 8：深入核心 | QObject worker、QThread、跨线程信号 | 将转码核心抽为库并直接调用 | GUI 不依赖命令行；后台工作正确结束；资源释放可验证 |

第七课完成批量队列与任务状态的第一部分，第八课从日志显示解封装估算进度，第九课改进取消与临时输出清理。第十课支持选择 1～3 个同时转码任务，默认 1。第十一课增加结构化进度消息，后续修订为依据封装阶段时间戳估算整体转码进度。第十二课用绘制代理在批量表格中显示每项进度条。第十三课支持按任务查看批量日志，并在批量页收起单文件路径控件。之后的界面修订将模式选择固定在窗口上方；第十四课增加日志复制和清空操作。第十五课为单文件和每项批量任务记录实际耗时。

阶段 1—4 只使用 Qt，不链接 FFmpeg，帮助你分清 GUI 问题与转码问题。阶段 5 得到第一版可用工具。阶段 8 是后续深入方向，不是第一版的前置条件。

## 每一课的做法

1. 说明这次运行后应看到什么。
2. 每次只引入少量新类或概念，说明它们与现有 C++ 知识的关系。
3. 改一个或少数几个文件，解释关键代码后构建。
4. 按完成标准实际操作，记录结果。
5. 自己做一个小改动，例如修改按钮行为或新增参数，能够说明原因后再进入下一课。

## 需要逐步回答的问题

- `app.exec()` 为什么让窗口一直响应？
- 按钮发出信号后，哪个函数会执行？
- `QMainWindow` 为什么需要 central widget 承载布局？
- 对象由父对象管理时，生命周期是怎样的？
- 为什么在按钮回调中等待转码结束会卡住窗口？
- QProcess 的异步进程与 QThread 的工作线程有什么区别？
- 如何判断后端真正完成，而不是只看见“启动成功”？

## 暂时采用的选择

先做 Windows、单文件、本地 MP4 转码；默认旋转 0°、倍速 1.0、视频 MPEG4、音频 AC3，与原 `ProcessingConfig` 默认值一致。用户可以选择 H.264/AAC，实际可用性需要后端运行验证。

先手写 Widgets 界面，方便看清对象、布局和连接；熟悉后再用 Designer 复刻。播放预览放在后续扩展，不与第一版转码混在一起。

学习参考：[Qt Widgets](https://doc.qt.io/qt-6.8/qtwidgets-index.html)、[信号与槽](https://doc.qt.io/qt-6.8/signalsandslots.html)、[QProcess](https://doc.qt.io/qt-6.8/qprocess.html)、[QThread](https://doc.qt.io/qt-6.8/qthread.html)。在线 Qt 6.8 文档可能显示更新的补丁号，本机版本以安装目录为准。
