# v1.0 展示版交付检查（2026-10-26）

本记录区分本机已验证的结果与仍需人工完成的验收。测试环境为 Windows 11、Qt 6.8.3、MinGW 13.1、CMake + Ninja、FFmpeg 4.4 shared SDK。源码仓库不包含第三方 SDK、测试媒体和打包产物。

## 本机已执行

1. 从提交后的源码创建独立本地检出目录，未复用原工作目录的 CMake 缓存；CMake 配置与完整构建均成功。此机的 Ninja 来自 CLion，需用 `CMAKE_MAKE_PROGRAM` 指定，或将 `ninja.exe` 加入 `PATH`。
2. 在全新构建目录运行 `ctest --output-on-failure --parallel 4`：11/11 通过，包含媒体分析、真实转码、批量队列、取消和输出保护测试。
3. 从全新构建目录运行 `scripts/package.ps1` 生成本地候选包。包内 GUI、后端二进制与构建目录中的对应文件哈希一致；`ffprobe.exe`、Qt 与 FFmpeg 运行依赖均被复制。
4. 在只保留候选包与 Windows 系统目录的 `PATH` 下，使用包内后端转码一段 4 秒合成 MP4；后端退出码为 0。包内 `ffprobe` 读取输出退出码为 0，识别出视频、音频两路流，文件大小约 734 KB，容器时长 4.032 秒。
5. Qt 测试程序截取并检查了 README 中的两张界面截图。截图素材由测试生成，不包含用户的 `input/` 或 `output/` 文件。

以上验证是在**同一台 Windows 电脑**完成。一次将候选包后端输出指向独立检出目录的构建根目录时，Windows 返回了“拒绝访问”；改用本项目的忽略测试目录后，同一候选包转码成功。该现象说明目标目录的访问权限仍需在目标机器上检查；本轮没有将其归因为转码逻辑故障。

## 下一台 Windows 电脑的人工验收

将整个候选包复制到一台未安装本项目 Qt / FFmpeg SDK 的 Windows 电脑，并逐项记录结果：

1. 启动 `QtFFmpegStudio.exe`，选择带音视频流的 MP4；确认视频信息出现，并能选择输出路径。
2. 完成普通、90° 旋转、0.5x 和 2.0x 转码；播放开头、中间与结尾，观察画面方向和音画同步，听是否出现断音。倍速时音调改变是当前实现的已知行为。
3. 添加至少三个批量任务，分别试用并发数 1、2、3；检查每项进度、耗时、日志和输出文件。
4. 取消运行中的单文件与批量任务；确认界面恢复，未留下本次任务的临时输出。
5. 用损坏 MP4 和无音轨 MP4 检查分析提示与单文件转码按钮状态。

人工验收完成前，本目录称为 **v1.0 候选包**。独立机器表现、真实媒体兼容性、主观音画质量与性能提升不由本机自动化结果推断。
