# 第十课：选择批量同时转码任务数

这一课把批量页从固定顺序执行升级为**最多同时运行 1、2 或 3 个后端进程**。默认仍是 1。每个进程负责一个任务，拥有自己的日志、解封装进度、最终结果和取消操作。后端内部已有六线程转码流水线；这里的“同时转码任务数”指运行中的文件数量，并非 Qt 线程池大小。

## 一、在 CLion 中一步步体验

1. 关闭旧窗口，重新加载 CMake，构建并运行 `QtFFmpegStudio`。打开“批量队列”页签，找到“同时转码任务数”，可选 1、2、3。
2. 先选 **1**，加入三个带音视频的 MP4，启动队列。表格一次只有一项“运行中”，前一项结束后下一项才开始。
3. 清空任务，改选 **2**，重新加入三个文件。启动后观察最多两项“运行中”，有一项结束便补进下一项。运行时选择框被禁用；队列结束后恢复。
4. 再试 **3** 与四个文件。运行时点击“停止队列”：已开始的项收到取消请求，尚未开始的项标为“已取消”；所有运行中进程退出后才显示汇总。
5. 关闭并重新打开窗口，确认你选的并发数得到恢复。成功的输出请播放，检查视频、音轨和参数效果。

## 二、读代码：谁决定下一项何时开始

[BatchWidget](../../src/batchwidget.cpp) 的 `pumpQueue()` 是调度器：只要 `running_.size() < maxConcurrent()`，它就找一个 Pending 任务并启动。后端发出 `finished` 后，当前任务从 Running 映射中移走，再用一次排队的事件循环调用补充空位。因此不会在 GUI 线程阻塞等待，也不会无限创建进程。

```text
Pending 任务 ──填充空位──▶ Running（最多 1～3 项）
                         │ 各自的 QProcess 发出 finished
                         ▼
                     成功 / 失败 / 已取消
                         │
                         └── 安排下一次补位
```

[BatchTaskModel](../../src/batchtaskmodel.cpp) 给每项分配稳定 `id`。每个 `BackendProcess` 的信号回调都带着自己的任务 ID；更新进度或结果前，通过 ID 找到所属行。批量日志也逐行加上 `[#任务ID]`，便于分清两个同时运行的进程。每项在加入队列时仍保存独立的参数快照；启动前仍检查输入、输出路径，后端仍拒绝覆盖已有输出。

“停止队列”会先将 Pending 项标为取消，再向 Running 映射里的**每个**后端发送取消请求。调度器看见停止标志后不再启动新项，等所有运行项退出才汇总。第九课的临时文件清理由各自的 `BackendProcess` 完成。

## 三、为什么没有用 Qt 线程池

本项目的 GUI 用 `QProcess` 启动独立的 `FFmpegProjectBackend.exe`。Qt 的事件循环已经可以同时监听多个子进程的信号；并发上限只需要控制正在运行的进程数量。把 `QProcess` 放进 Qt 线程池不会替代后端内部的六线程流水线，也不会自动解决进度归属、取消或输出保护。本课让每个进程留在 GUI 线程的事件循环中，以异步信号报告状态。

同时运行更多文件会增加 CPU、内存和磁盘负载，所以先限制为 1～3；机器较忙时建议选 1。设置由 [MainWindow](../../src/mainwindow.cpp) 写入 `QSettings` 的 `batch/maxConcurrent`；旧设置缺少这个键或值无效时，使用默认值 1。

## 四、验证与练习

[批量测试](../../tests/test_batch_widget.cpp)覆盖默认串行、上限 2 的同时运行与失败补位、上限 3 的多进程停止、任务日志归属、独立进度与输出音视频流。[模型测试](../../tests/test_batch_model.cpp)验证任务 ID 不因清空表格而复用；[设置测试](../../tests/test_engineering.cpp)验证保存和无效值回退。可用 `ctest --test-dir build --output-on-failure` 复核全部测试。

请自己完成两个练习：

1. 在 `pumpQueue()` 找到限制同时运行数量的条件。假设上限是 2、队列里有 5 项，画出第一项失败后哪一项会补位。
2. 找到 `cancelQueue()`。解释为什么必须等待所有 Running 项的 `finished`，才能发出队列结束信号。

自动测试使用短媒体；自己的视频仍需手工播放核对。批量并发与后端内部线程是两层不同的并发，不要把“并发数 3”理解为后端只有 3 个线程。
