# 第十三课：按任务查看批量日志

这一课解决两处界面问题：并发任务的日志混在同一文本框时不方便追错；切到批量页时，上方单文件输入、输出和检查控件占了空间。

## 在 CLion 中逐步验收

1. 关闭旧窗口，重新加载 CMake，构建并运行 `QtFFmpegStudio`。
2. 切到“批量队列”。上方应保留旋转、倍速、音视频编码等**共用转码参数**；单文件输入、输出、路径检查和参数预览会收起。切回“真实转码”，这些控件应重新出现，原先填写的路径不丢失。
3. 在批量页添加两段 MP4，设置同时转码任务数为 2，开始队列。默认“全部日志”按到达顺序显示，并带有任务编号。
4. 点击第一行，下面只显示第一项的日志；点击第二行，只显示第二项。也可以从“查看日志”下拉框直接选任务，或切回“全部日志”。完成后仍能查看结果与失败原因。
5. 加入一段损坏的 MP4，观察该项失败后选中其行，能看到失败信息。点击“清空任务”后，下拉框应只剩“全部日志”，旧日志不再显示。

课程构建使用的命令如下；你的 CLion 若使用其他构建目录，请替换目录名：

```powershell
$env:PATH = 'D:\QT\Tools\mingw1310_64\bin;D:\QT\6.8.3\mingw_64\bin;' + $env:PATH
cmake --build .\cmake-build-codex-lesson4 --parallel 4
ctest --test-dir .\cmake-build-codex-lesson4 --output-on-failure
```

## 读代码：为什么按 ID 保存日志

[BatchWidget](../../src/batchwidget.cpp)为每个任务保存稳定的 `task.id`。后端的日志信号仍只会更新所属任务；完整日志行进入最多 2000 行的记录列表，记录里同时放任务 ID 和文本。查看“全部日志”时按原顺序显示；选一项时只保留匹配 ID 的行。日志显示框也限制 2000 行，避免长视频不断增加内存。列表只保留最近的 2000 行，因此很早的日志可能被后续日志挤掉。

表格的 `QItemSelectionModel::currentRowChanged` 告诉程序用户选中了哪一行，再用该行对应的任务 ID 选择日志；点击已经选中的行也能从“全部日志”切回该项。下拉框选择与表格选择走同一套日志过滤。转码前校验失败和后端结束结果也写入对应任务日志，方便事后回看。

## 读代码：为什么参数仍然可见

[MainWindow](../../src/mainwindow.cpp)将单文件路径控件和单文件工具控件分别放入容器，依据当前模式切换可见性。后续修订将页面选择改为顶部 `QTabBar` 与 `QStackedWidget`，参见[顶部导航修订](../updates/top-navigation.md)。`optionsGroup_` 是两种转码共用的参数来源，所以批量页保留它。隐藏控件只影响显示，不清空输入、输出和设置值；切回单文件页能继续编辑和检查。
